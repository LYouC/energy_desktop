# 业务模型与操作

| 文件                                 | 内容                                                              |
| ------------------------------------ | ----------------------------------------------------------------- |
| [model.ts](model.ts)                 | 任务、安排、方案、工作区和命令的 Zod schema、类型及初始值。       |
| [operations.ts](operations.ts)       | `applyCommand` 校验并应用任务、安排、方案、能量、偏好与会话命令。 |
| [recurrence.ts](recurrence.ts)       | 解析重复轮次与逾期，并投影今日安排。                              |
| [conversations.ts](conversations.ts) | 通过最近活动时间组织可见历史，处理会话删除及保留上限。            |

界面、Agent 与持久化共用这些规则。调用方负责获取当前状态和保存操作结果。

任务属性包括名称 `title`、状态 `status`、重要性 `importance`、预计开始 `startDate`、预计完成 `expectedDate`、说明 `description`、所属任务 `parentId`，以及系统维护的 `id/version/updatedAt`。普通任务和子任务共用 `newTask(parentId?)` 与同一 schema。日期可空，业务入口校验有效日历日期及开始不晚于完成。说明承载目标、背景和进展等内容。

重要性取 `high`、`medium`、`low` 或 `null`。任务创建时默认为 `null`，完整的 `saveTask` 命令包含该字段，传入 `null` 清空标注。

安排独立于任务日期，安排、取消和完成均保留预计起止日期。`saveTask` 保存任务属性，安排通过独立命令操作。父子关系表示包含，校验存在性与循环。

`schedulableTodayTasks` 查询可新增当天安排的开放一次性任务，排除已有当天安排或移除记录的任务。`unscheduledTasksDue` 在此基础上按预计完成日期过滤。`scheduleToday` 与 `scheduleDueToday` 分别供所有任务和预计完成区使用，均在写入时重新核对本地日期和资格，并以任务名追加安排。

普通安排使用调整卡记录的目标日期。`newArrangementOnly` 标记新增整项安排，应用时校验目标日期的入队资格。界面通过 `respondToCard` 确认单张卡。业务校验失败时保留任务和安排，单独保存卡片失败原因。对话预演与提交共用严格的 `resolve`，失败会回滚并返回错误。

`moveTodayGroups` 在同一次命令中交换两组当天待推进安排的相对位置，保留各组内部顺序。子任务同级调序使用 `move`。

`childTaskSchema` 从任务可编辑属性复用子任务字段，拆分时所属任务由父任务确定。子任务可仅提供名称，也可保存自己的说明、状态与预计起止日期。子任务日期沿用普通任务校验，工具拒绝未知字段。

`model.ts` 定义任务、按日期安排、方案、会话和有限 Command。`operations.ts` 是业务变更入口，返回独立的新状态，失败时原状态完整保留。任务版本用于识别过期方案，状态 revision 用于持久化并发校验。方案按任务保存调整卡，卡内共用理由和状态。`resolve` 通过 `proposalId` 和 `cardIds` 选择完整卡片。接受时在同一份状态中校验并应用卡内动作，失败时保留原业务数据和卡片状态。拒绝只变更卡片状态，重复决定不重复执行。

今日普通任务勾选走 `setTaskDone`。完成父项会在同一命令中完成各层一次性子任务，`saveTask` 将后来新增的子任务同步为完成。单项恢复时检查上级完成状态。今日待推进由 `isArrangementPending` 结合任务整体状态与安排记录判断。删除父任务会删除后代，界面必须明确展示此范围。

`unscheduledTasksDue` 查询预计今天完成的未安排待办。`completedUnscheduledTasksDue` 使用同一套未安排一次性任务范围，按预计日期和整体完成状态查询今日完成区的补充任务。

拆分建议可用子项的 `todayScope` 指定当天安排范围。整张调整卡接受后才创建子任务及安排。子任务按卡片日期安排。

## 重复任务

重复规则由顶层任务定义，子任务沿用父任务的规则和轮次。总表从当前轮次推导状态，今日页从当天安排读取执行顺序。任务 ID 和应做日期贯穿命令及完成记录。数据归属和跨模块流程见 [技术方案](../../docs/技术方案.md#重复任务的日期与状态)，使用场景见 [重复任务说明](../../docs/重复任务.md)。

| 入口                                                           | 保持的规则                                                                                                                                                                         |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `effectiveRecurrences`                                         | 解析各层任务从顶层任务沿用的重复规则。                                                                                                                                             |
| `latestRecurrenceDate`、`recurrenceProgress`                   | 从规则和启用区间找最近应做日。结合跳过、停止和完成记录，返回显示日期 `target`、逾期 `overdue`、可勾选 `canComplete`、撤销目标 `undo`。完成后仍以原一轮为撤销目标，下次到期才切换。 |
| `synchronizeRecurrence`                                        | 刷新当天重复安排，保留仍有效条目的位置。父任务当轮已完成时，后续加入的子任务也显示当轮已完成。顶层任务是否完成以 `repeatCompletions` 为准。名称与祖先从任务读取。                  |
| `setOccurrenceDone`                                            | 当前未完成轮次到应做日后可完成。顶层任务勾选时记录应做日和勾选日，撤销时删除该记录。要单独撤销子任务的完成，须先撤销该轮已完成的上级。                                             |
| `skipOccurrence`、`restoreOccurrence`                          | 跳过主任务时移出该规则的当天组。只在当天且规则仍有效时恢复，按快照里的相邻项重放位置。离开重复组后清除来自原组的跳过记录。                                                         |
| `saveTask`、`stopRecurrence`、`resumeRecurrence`、`deleteTask` | 保存规则后立即刷新今天，保留完成历史。恢复从当天重新开始匹配规则。删除按任务树清理任务、安排、跳过、排期状态与完成记录。                                                           |

普通的跨日撤销以 `undo` 为准。当前命令也接受撤销当天仍保留的已完成安排，因此停止后的今日完成卡片虽已收起勾选框，通过对话明确指定该轮仍可能撤销。界面和对话的处理边界见 [待确认需求](../../docs/待确认需求.md#停止重复后的完成更正)。

## 会话与验证

`conversations.ts` 以最近活动时间排序，最多保留 1000 个会话。Agent 整理记忆后，会话保存 `agentMemory`。Agent 动作的授权语义、工作记忆与历史查询由 [Agent 模块](../agent/README.md)说明。

一键优化以 `source: "optimizeToday"` 标记并保存用户消息，保留同一会话的草稿。普通用户消息清空输入草稿。

`npm test` 中的 `domain.test.ts`、`workspace.test.ts`、`conversations.test.ts` 和 `task-fields.test.ts` 覆盖状态变更、方案、会话和任务日期规则。`recurrence.test.ts` 覆盖到期勾选、跨日保持、逾期补勾、规则编辑、跳过、停止和级联删除。`agent-domain.test.ts` 覆盖同任务整卡确认、跨任务独立确认和幂等。`agent-recurrence.test.ts` 覆盖对话操作、规则变更与当天操作合卡、跨日校验和混合操作回滚。
