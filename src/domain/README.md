# 业务模型与操作

| 文件                                 | 内容                                                              |
| ------------------------------------ | ----------------------------------------------------------------- |
| [model.ts](model.ts)                 | 任务、安排、方案、工作区和命令的 Zod schema、类型及初始值。       |
| [operations.ts](operations.ts)       | `applyCommand` 校验并应用任务、安排、方案、能量、偏好与会话命令。 |
| [recurrence.ts](recurrence.ts)       | 计算重复规则的下一次日期，结算过去和当天的实例。                  |
| [conversations.ts](conversations.ts) | 通过最近活动时间组织可见历史，处理会话删除及保留上限。            |

界面、Agent 与持久化共用这些规则。调用方负责获取当前状态和保存操作结果。

任务属性包括名称 `title`、状态 `status`、重要性 `importance`、预计开始 `startDate`、预计完成 `expectedDate`、说明 `description`、所属任务 `parentId`，以及系统维护的 `id/version/updatedAt`。普通任务和子任务共用 `newTask(parentId?)` 与同一 schema。日期可空，业务入口校验有效日历日期及开始不晚于完成。说明承载目标、背景和进展等内容。

重要性取 `high`、`medium`、`low` 或 `null`，已有数据缺失时读取为 `null`。用户通过 `saveTask` 编辑标注，显式传入 `null` 清空标注。省略该字段的旧版命令沿用已有标注。

安排独立于任务日期，安排、取消或历史阶段完成均不改预计起止日期。`saveTask` 只保存任务属性，旧复合命令携带 `arrangement` 时会被严格拒绝，不再隐式创建或覆盖安排。父子关系只表示包含，校验存在性与循环；不再维护结构化依赖。

`schedulableTodayTasks` 查询可新增当天安排的开放一次性任务，排除已有当天安排或移除记录的任务。`unscheduledTasksDue` 在此基础上按预计完成日期过滤。`scheduleToday` 与 `scheduleDueToday` 分别供所有任务和预计完成区使用，均在写入时重新核对本地日期和资格，并以任务名追加安排。

Agent 新增当天整项安排的调整卡用 `todayOnly` 标记。在接受时重新核对日期及 `schedulableTodayTasks`，避免跨日写入或覆盖已有安排。v5 旧 `advanceTask` 待接受卡在升级时失效并保留历史，其他旧共享安排与阶段卡继续按原规则读取和处理。

`moveTodayGroups` 在同一次命令中交换两组当天待推进安排的相对位置，保留各组内部顺序。子任务同级调序使用 `move`。

Agent 动作与草稿均已使用新属性。childTaskSchema 从任务可编辑属性复用子任务字段，拆分时所属任务由父任务确定。子任务可仅提供名称，也可保存自己的说明、状态与预计起止日期。旧方案读取时将 children.goal 转入 description，新工具协议拒绝旧字段，避免静默丢失内容。子任务日期沿用普通任务校验。

`model.ts` 定义任务、按日期安排、方案、会话和有限 Command。`operations.ts` 是业务变更入口，返回独立的新状态，失败时原状态完整保留。任务版本用于识别旧方案，状态 revision 用于持久化并发校验。方案按任务保存调整卡，卡内共用理由和状态。`resolve` 通过 `proposalId` 和 `cardIds` 选择完整卡片。接受时在同一份状态中校验并应用卡内动作，失败时保留原业务数据和卡片状态。拒绝只变更卡片状态，重复决定不重复执行。旧方案仍按原条目分别处理。

今日普通任务勾选走 `setTaskDone`。完成父项会在同一命令中完成各层仍开放的一次性子任务，恢复只改目标项并设为未开始。重复实例、重复模板遗留的临时安排及旧普通阶段保留各自的执行记录，按 `stage` 处理。今日待推进由 `isArrangementPending` 结合任务整体状态与安排记录判断。删除父任务会删除后代，界面必须明确展示此范围。

`unscheduledTasksDue` 查询预计今天完成的未安排待办。`completedUnscheduledTasksDue` 使用同一套未安排一次性任务范围，按预计日期和整体完成状态查询今日完成区的补充任务。

拆分建议可用子项的 `todayScope` 指定当天安排范围。整张调整卡接受后才创建子任务及安排。接受时核对原建议的本地日期，旧拆分记录仍可正常读取和处理。

重复模板在任务中保存 `recurrence`，支持每天、每周自选星期和起止日期内每天。`synchronizeRecurrence(state, date)` 按本地日期结算到当天。每个模板每日至多一条实例，同日已有安排沿用原位置、范围与完成状态。实例保存当时的名称和祖先 ID，调序、改范围、完成与移除只增加实例版本。规则编辑从次日生效，`createOccurrence` 可为仍有有效规则的模板补加当天一次，已有或已移除时不重复生成。

`effectiveRecurrences(tasks)` 由显式规则和父子关系计算有效规则。子任务没有独立规则时继承最近的重复祖先，状态和游标按各自任务保存。父规则变化同步更新受影响的子任务版本并保留当天实例；没有游标的旧子任务从首次按新版本读取的当天结算。

当天的实例和手动临时安排可以完成、调序、修改范围或移除。移除重复实例时单独保存当天能撤销所需的数据，实例随即从今日队列移除；临时安排移出沿用普通取消安排。删除模板会停止后续生成，已产生的实例保存在工作区中，今天这次仍可操作。普通任务与子任务的级联删除同样保留已产生的重复实例。Agent 通过方案应用器复用保存、删除和当天实例操作。重复条目校验本地日期，当天实例还校验快照，模板删除时核对后代范围。

验证使用 `npm test`。Agent 动作复用同一业务入口和方案规则。

`conversations.ts` 以最近活动时间排序，最多保留 1000 个会话。工作区 schema 允许旧会话省略 `agentMemory`。Agent 动作的授权语义、工作记忆与历史查询由 [Agent 模块](../agent/README.md)说明。

一键优化以 `source: "optimizeToday"` 标记并保存用户消息，保留同一会话的草稿。普通用户消息仍清空草稿，旧消息无需迁移。

`npm test` 中的 `domain.test.ts`、`workspace.test.ts`、`conversations.test.ts` 和 `task-fields.test.ts` 覆盖状态变更、方案、会话和任务日期规则。`recurrence.test.ts` 覆盖日期结算、同日复用、规则编辑、移除撤销和模板删除。`agent-domain.test.ts` 覆盖同任务整卡确认、跨任务独立确认和幂等。`agent-recurrence.test.ts` 覆盖对话动作、模板与实例同卡、跨日及混合操作回滚。
