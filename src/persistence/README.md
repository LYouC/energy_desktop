# SQLite 持久化

| 文件                     | 内容                                                                                                                                            |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| [storage.ts](storage.ts) | `WorkspaceDatabase` 提供 `currentDate`、`load`、`execute`、`commitAgentTurn` 和 `close`。加载时校验工作区，写入时核对 revision 并在事务中更新。 |

模块使用 `node:sqlite`，把工作区保存为一条带版本的 JSON 记录。手动修改复用 [领域命令](../domain/operations.ts)，Agent 写入复用 [整轮业务应用](../agent/turn.ts)。事务同时提交任务、方案、会话与工作记忆，失败时保留上一份状态。桌面宿主传入数据库路径，正常运行使用 userData 下的 `workspace.db`。

界面卡片操作在事务内读取最新工作区，按卡片 ID、处理状态和关联任务或实例版本校验。业务拒绝导致的执行失败只提交卡片的失败原因。

读取工作区或提交操作时，由业务层按本地日期补齐重复任务实例。保存日期结算与工作区版本使用同一事务；如果跨日结算改变了调用方所持版本，调用方刷新后可重试。Agent 最终事务也核对预演所用的日期，跨日需重新分析。模板删除后已生成的实例保留在同一份工作区中。

子任务的有效重复规则在结算时读取父子关系，首次获得规则的子任务从当天结算。重复实例创建时同时写入名称、祖先 ID 与初始版本。

## 开发期工作区格式

当前格式为 v8。SQLite 在同一事务内创建工作区、写入初始状态和设置 `user_version`，每次加载用当前 schema 校验快照。格式版本变更时使用空工作区。并发检查使用快照内的 `revision`。

要在原数据目录开始新工作区，先退出应用，将目录内的 `workspace.db`、`workspace.db-wal` 和 `workspace.db-shm`（存在时）移到一处，再启动。此时应用会新建空工作区，原目录的模型配置仍可使用。开发时也可设置 `XIXU_DATA_DIR` 指向新的目录。窗口与数据目录设置见 [桌面宿主](../desktop/README.md)。

运行 `npm test` 验证格式检查、重开、并发版本、回滚与 Agent 整轮提交。运行 `npm run test:desktop` 验证 Electron 内的 SQLite 写入和重启恢复。
