# SQLite 持久化

| 文件                           | 内容                                                                                                                             |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| [storage.ts](storage.ts)       | `WorkspaceDatabase` 提供 `load`、`execute`、`commitAgentTurn` 和 `close`。加载时校验工作区，写入时核对 revision 并在事务中更新。 |
| [migrations.ts](migrations.ts) | 将 v1 工作区转成当前任务字段，由数据库初始化过程在事务内调用。                                                                   |

模块使用 `node:sqlite`，把工作区保存为一条带版本的 JSON 记录。手动修改复用 [领域命令](../domain/operations.ts)，Agent 写入复用 [整轮业务应用](../agent/turn.ts)。事务同时提交任务、方案、会话与工作记忆，失败时保留上一份状态。桌面宿主传入数据库路径，正常运行使用 userData 下的 `workspace.db`。

模式版本为 3。v2 工作区校验后原样升级，已有任务保持一次性。`migrations.ts` 将 v1 任务的目标、背景、进展、阻力、下一步、硬截止和前提要求合入说明，保留预计完成日期和原有每日安排。旧推进日期不用于推断预计开始日期。旧待接受方案失效，清除使用旧字段的待创建任务草稿。迁移与版本更新在同一事务中完成，失败回滚。

读取工作区或提交操作时，由业务层按本地日期补齐重复任务实例。保存日期结算与工作区版本使用同一事务；如果跨日结算改变了调用方所持版本，调用方刷新后可重试。模板删除后已生成的实例保留在同一份工作区中。

重要性是工作区 JSON 任务的可空字段。缺少该字段的 v2 数据按未设置读取，用户标注随事务保存。v1 迁移同样将重要性初始化为未设置。

运行 `npm test` 验证迁移、失败回滚、磁盘重开、并发版本与 Agent 整轮提交。运行 `npm run test:desktop` 验证 Electron 内的 SQLite 写入和重启恢复。窗口及数据目录设置见[桌面宿主](../desktop/README.md)。
