# SQLite 持久化

| 文件                     | 内容                                                                                                                                            |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| [storage.ts](storage.ts) | `WorkspaceDatabase` 提供 `currentDate`、`load`、`execute`、`commitAgentTurn` 和 `close`。加载时校验工作区，写入时核对 revision 并在事务中更新。 |

模块使用 `node:sqlite`，把工作区保存为一条带版本的 JSON 记录。手动修改复用 [领域命令](../domain/operations.ts)，Agent 写入复用 [整轮业务应用](../agent/turn.ts)。事务同时提交任务、方案、会话与工作记忆，失败时保留上一份状态。桌面宿主传入数据库路径，正常运行使用 userData 下的 `workspace.db`。

界面卡片操作在事务内读取最新工作区，按卡片 ID、处理状态、任务版本和当天安排版本校验。业务拒绝导致的执行失败只提交卡片的失败原因。

读取或提交时按本地日期刷新当天的重复安排，在同一事务内更新工作区版本。`repeatSchedules` 保存排期的生效区间和停止状态，`repeatCompletions` 保存已经勾选的轮次，今日顺序与子任务状态在当天安排中维护。跨日使调用方版本过期时刷新后可重试。Agent 最终事务也核对预演所用日期。删除任务时同时清理相关安排和记录。 [重复任务数据归属](../../docs/技术方案.md#重复任务的日期与状态)

## 开发期工作区格式

当前格式为 v11。重复规则只保存在顶层任务，加载快照时校验这一约束。当天重复安排保存共享的安排字段及安排版本，名称和祖先关系从任务读取。调整卡使用实际任务版本。SQLite 在同一事务内创建工作区、写入初始状态和设置 `user_version`，每次加载用当前 schema 校验快照。并发检查使用快照内的 `revision`。

`npm run dev` 启用 `resetOnFormatMismatch`。版本不匹配时，同一事务清空并重建工作区表以及版本标记。版本一致时正常打开。模型配置单独存放。

构建后启动和打包版保留不匹配的工作区并报告错误。若需在同一数据目录新建工作区，先退出应用，再移走 `workspace.db` 及同名的 `-wal` 和 `-shm` 文件。窗口与数据目录设置见 [桌面宿主](../desktop/README.md)。

运行 `npm test` 验证格式检查、重开、并发版本、回滚与 Agent 整轮提交。运行 `npm run test:desktop` 验证 Electron 内的 SQLite 写入和重启恢复。
