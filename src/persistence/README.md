# SQLite 持久化

| 文件                           | 内容                                                                                                                                            |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| [storage.ts](storage.ts)       | `WorkspaceDatabase` 提供 `currentDate`、`load`、`execute`、`commitAgentTurn` 和 `close`。加载时校验工作区，写入时核对 revision 并在事务中更新。 |
| [migrations.ts](migrations.ts) | 将旧任务字段和旧方案转为当前结构，由数据库初始化过程在事务内调用。                                                                              |

模块使用 `node:sqlite`，把工作区保存为一条带版本的 JSON 记录。手动修改复用 [领域命令](../domain/operations.ts)，Agent 写入复用 [整轮业务应用](../agent/turn.ts)。事务同时提交任务、方案、会话与工作记忆，失败时保留上一份状态。桌面宿主传入数据库路径，正常运行使用 userData 下的 `workspace.db`。

模式版本为 6。v2 至 v4 的旧方案每条变更各迁入一张卡，沿用条目 ID、理由与状态，保留逐条确认的历史语义。v5 升级保留历史阶段、手动临时安排和全部方案内容；其中旧 `advanceTask` 产生的待接受 `todayOnly` 卡状态置为已拒绝并标记 `invalidated`，界面显示「已失效」，避免升级后继续创建单次阶段推进。已接受或已拒绝的历史状态不变，其他共享安排卡仍按原规则处理。`migrations.ts` 将 v1 任务的目标、背景、进展、阻力、下一步、硬截止和前提要求合入说明，保留预计完成日期和原有每日安排。旧推进日期不用于推断预计开始日期。v1 待接受方案按原有规则标记失效，清除使用旧字段的待创建任务草稿。迁移与版本更新在同一事务中完成，失败回滚。

读取工作区或提交操作时，由业务层按本地日期补齐重复任务实例。保存日期结算与工作区版本使用同一事务；如果跨日结算改变了调用方所持版本，调用方刷新后可重试。Agent 最终事务也核对预演所用的日期，跨日需重新分析。模板删除后已生成的实例保留在同一份工作区中。

子任务的有效重复规则在结算时读取父子关系，无需改写原有任务或升级数据库模式。原先没有重复游标的子任务从首次结算的当天开始。

实例祖先 ID 和实例版本作为可选 JSON 字段兼容旧工作区。当天活动及已移除的旧实例在首次结算时从仍可查的父子关系补齐快照，随后保留快照。早于当天的旧记录不反推未保存的历史归属。

重要性是工作区 JSON 任务的可空字段。缺少该字段的 v2 数据按未设置读取，用户标注随事务保存。v1 迁移同样将重要性初始化为未设置。

运行 `npm test` 验证迁移、失败回滚、磁盘重开、并发版本与 Agent 整轮提交。运行 `npm run test:desktop` 验证 Electron 内的 SQLite 写入和重启恢复。窗口及数据目录设置见[桌面宿主](../desktop/README.md)。
