此刻的数据变化

选择权跟随本轮意图

“帮我分析”生成建议。“把英语移到明天”授权具体修改。“只接受英语”只应用英语整张调整卡。含糊指代需要核实。

能量与分析独立

手动改变能量只保存状态。主动发送消息后，Agent 才读取最新状态并分析。休息或完成任务的效果通过用户反馈了解。

凭据留在调用层

本地配置向模型服务提供认证。模型看到任务和会话上下文，Key 通过服务请求的认证通道使用。

查看编排、校验与模块职责

runtime.ts 使用真实对话轮次，每轮最多六个模型步骤，超时一百二十秒。readTask 查询任务，readConversation 查阅当前会话历史，calculateCapacity 核算时间。模型用 prepareTurn 提交交流或操作的语义决定、具体动作与可选记忆。程序预演本轮动作，对每张新卡试应用并返回回执，模型随后生成自然语言终答。本轮完整结果通过一次事务保存。

src/agent/turn.ts 把模型选定的动作转换成有限业务操作。任务属性和字段归属见 产品需求。创建时机、授权和指代由模型理解，程序检查结构、任务关系、会话归属和版本。修改范围用 updateArrangement 明确指定原安排，支持原子转由子任务承接。

对话通过 resolve 引用当前会话的 proposalId 和 cardIds，界面的确认按钮提交单张卡。operations.ts 按整卡校验和应用变更。runtime.ts 比较运行前后任务、安排、方案、能量、偏好和会话记忆的快照。storage.ts 在事务内检查数据版本，一次保存本轮操作、记忆与最终回复。

config.ts 管理 HTTPS 服务地址、模型与凭据。设置界面输入的 Key 使用 Electron safeStorage 加密保存，也可从执行进程的环境变量读取。界面查询配置只取得服务地址、模型及是否已配置 Key。更换服务地址时需提供相应凭据。

同一套 Agent 循环承担澄清、拆分、安排与受阻协助。模型先决定操作并读取回执，随后生成的自然语言正文支持流式预览。工具步骤中的文字属于中间过程，正式业务变更与会话记录以事务保存成功为准。

系统边界见 技术方案。对话场景与结果分别见 Agent 场景用例 和 Agent 验证记录。
