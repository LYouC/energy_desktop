此刻的数据变化

选择权跟随本轮意图

“帮我分析”生成建议。“把英语移到明天”授权具体修改。“只接受英语”只应用对应部分。含糊指代需要核实。

能量与分析独立

手动改变能量只保存状态。主动发送消息后，Agent 才读取最新状态并分析。休息或完成任务的效果通过用户反馈了解。

凭据留在调用层

本地配置向模型服务提供认证。模型看到任务和会话上下文，Key 通过服务请求的认证通道使用。

查看编排、校验与模块职责

runtime.ts 使用真实对话轮次，每轮最多六个模型步骤，超时一百二十秒。readTask 查询任务，readConversation 查阅当前会话历史，calculateCapacity 核算时间。模型用 prepareTurn 提交交流或操作的语义决定、具体动作与可选记忆。程序预演并返回回执，模型随后生成自然语言终答。本轮完整结果通过一次事务保存。

shared/agent.ts 把模型选定的动作转换成有限业务操作。任务共用名称、状态、预计开始、预计完成、说明和所属任务六项属性。模型判断哪些信息值得补充，用户跳过时继续落地。背景、硬截止和停点合入说明，预计日期与每日安排独立保存。创建时机、授权和指代由模型理解，程序检查结构、任务关系、会话归属和版本。修改范围用 updateArrangement 明确指定原安排，支持原子转由子任务承接。语义判断通过真实场景持续评审。

operations.ts 维护任务关系、完成状态和方案接受规则。runtime.ts 比较运行前后任务、安排、方案、能量、偏好和会话记忆的快照。storage.ts 在事务内检查数据版本，一次保存本轮操作、记忆与最终回复。

config.ts 管理 HTTPS 服务地址、模型与凭据。设置界面输入的 Key 使用 Electron safeStorage 加密保存，也可从执行进程的环境变量读取。界面查询配置只取得服务地址、模型及是否已配置 Key。更换服务地址时需提供相应凭据。

同一套 Agent 循环承担澄清、拆分、安排与受阻协助。模型先决定操作并读取回执，随后生成的自然语言正文支持流式预览。工具步骤中的文字属于中间过程，正式业务变更与会话记录以事务保存成功为准。

本页用于解释编排。实际模型能力与各场景的验证结果见项目测试记录，具体行为依据 产品需求 和 Agent 场景用例。
