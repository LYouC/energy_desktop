# 产品需求

本文定义产品范围、用户可见行为、默认值和验收条件。交付顺序及当前进度见 [开发计划](开发计划.md)。

## 1. 目标与范围

开发一个桌面 Agent Todo。用户通过自然对话表达想做的事、约束和感受；Agent 结合已有任务和背景，帮助规划、拆分、启动、推进、调整与收尾。优先追求重要任务的实际进展、可持续的节奏和用户的选择权，不能只用完成数量判断效果。

灵感来自用户阅读《反倦怠能量站》后的实践想法：精力有限，持续受挫可能让人泄气，可见进展和休息有助于恢复行动意愿。应用以此理解用户处境，同时允许 Agent 使用更合适的规划方法。

产品应贯穿完整任务过程：既处理安排过满、目标过大，也处理不知如何开始、执行受阻与泄气。技术实现可分阶段，不将产品预先限制为只解决其中一种问题。

当前包含应用内任务管理、可跟踪子任务、重复任务与执行记录、自动整理背景、Agent 对话与规划、离散能量状态、本地保存，以及浅色/深色主题。一次性任务和重复任务都可通过对话或手动创建。

当前不包含外部 Todo 来源与同步、收集箱、“接下来”导航、云端账号与多端同步、后台自主执行。任务图是明确的未来方向：直观展示一天的安排；图形形式、时间精度和依赖表达在后续设计时决定，现在不实现、不新增图形库。

## 2. 任务与计划的含义

| 概念 | 含义 |
| --- | --- |
| 任务 | 要完成的一项工作，可跨多天。可编辑名称、重要性、说明与所属任务，一次性任务还可编辑整体状态和预计起止日期。 |
| 子任务 | 有所属任务的任务，与其他任务共用编辑器。父子关系表达包含。 |
| 重复模板 | 设置了重复规则的任务，在「所有任务」中占一行，规则决定实例出现的日期。 |
| 重复实例 | 模板在某个本地日期生成的安排，保存当时的任务名称、本次范围和完成结果。 |
| 今日安排 | 统一展示当天推进的普通阶段和自动加入的重复实例，包含行动顺序、推进范围和必要的休息。 |
| 下一步行动 | 用户此刻能开始、知道做到哪里结束的具体动作。 |
| 任务背景 | 为理解和继续推进任务保留的简明上下文，见 R02。 |
| 规划方案 | Agent 提出的、尚未全部接受的变更及理由；与已生效安排区分。 |

一次性任务在安排后进入今日行动顺序，重复模板按规则生成当日安排。完成今日阶段或重复实例只记录本次结果。完成子任务后，父任务仍按自身完成条件判断，已列子任务全部完成但目标尚未满足时，需要检查遗漏。

总任务单管理任务与重复模板，今日安排记录当天的执行范围和结果，供未来任务图使用。保留原目标和已协商的今日范围，避免重复计算父子任务的工作量。

## 3. 交互与功能要求

### R01：对话建立任务

用户主动表达是一次性任务的主要入口，可以从模糊想法开始。Agent 结合已有任务，只追问明显影响建议的关键条件，允许边交流边完善、暂估和“不知道”。已有任务的补充归入同一条记录。明确要求记录或修改时，Agent 按当前支持的操作和授权处理，试探性的想法不能自动成为今日承诺。重复任务的操作入口见 R11。

创建时机、用户是否已接受及指代对象由 Agent 结合多轮语义判断。Agent 自主概括标题、目标和背景，未知截止可留空。用户已经同意创建后直接落地，普通措辞不逐项确认。只有会实质改变目标、对象或用户承诺的歧义才需要追问。

### R02：形成并维护任务背景

Agent 从对话中整理任务缘由、预期结果、截止要求、当前进度、材料与前提、用户说出的困难、尝试过的方法、调整理由和下一步。用户无需重复手工整理。

背景可查看、修改、删除；保留与该任务有关的信息，不复制整段聊天。区分用户明确事实、暂估和 Agent 推测，不能把“拖了三天”写成已证实的“完美主义”。新信息纠正旧信息后，后续规划以修正结果为准。“昨晚没睡好”是有时效的状态，不能自动变成长久的人格或能力判断。

### R03：协商每日安排

综合真实截止、重要性、依赖、可用时间、用户偏好和当前状态，识别过量、连续高难度或缺少前提的计划。优先提出一份有判断的建议，说明先做什么、做到哪里、保住什么和让步什么，必要时给替代选项。

允许调整顺序、缩小今日范围、拆分、改期、插入休息、求助或等待条件。耗时未知时标为暂估，不编造容量，也不保证一定完成。硬截止无法同时满足时明确冲突，协商范围、截止或支持条件，不用默认加班吸收全部任务。用户拒绝建议后，在其新约束下继续协助，不反复劝说。

### R04：拆成可跟踪子任务

根据目标、已知进度和阻力拆分大任务；让每个子任务有具体产出与完成条件，必要时保留依赖。用户接受后形成实际任务结构，不能只在聊天中列几个步骤就算实现。

支持继续通过交流增补、合并、调整或进一步拆分，优先细化近期要执行的部分，避免过度拆分。明确当前适合开始的子任务和第一步，保持整体目标、今日目标与本轮结束条件可区分。

### R05：帮助启动和应对受阻

用户说“开始不了”“做不出来”“做得很烦”时，结合背景判断主要阻力，需要时简短核实。提供具体下一步：缩小入口、改变方法、补前置知识、降低本轮要求、求助、休息或重排。鼓励应基于实际处境与进展，不止于泛泛加油。

可以协商方法复查条件，例如多次尝试无进展后检查卡点。困难任务仍可能值得投入；用户希望继续挑战时帮助选择路径，不能一律建议逃离难题，也不能因挫败表达自行取消、改期或完成任务。

### R06：能量作为指导思想

做任务会产生消耗，达成目标或休息可能带来回收；能量理论用于理解节奏，不是唯一规划算法。Agent 可采用其他适合的方法，综合任务约束判断。

能量只用离散状态展示和输入上下文，不显示分数、百分比，不在后台用固定扣分与恢复公式假装精确。达成目标、弄清错因等可见进展可能提供积极反馈，休息有独立价值；不能保证休息或完成一项任务后必然恢复。

用户可手动改状态。**修改状态 → 保存与更新展示；主动请求分析 → 读取最新上下文并生成建议；接受建议 → 应用相应计划变更。** 三个行为独立。手改状态不发消息、不调用模型、不重排，用户可以改后继续执行原计划。

提供对话预设快捷入口，例如“我现在有些疲惫，请结合当前任务、进度和背景重新分析今天的安排”。预设使用发起时的最新状态，不能复用旧标签。即使没点击该入口，之后主动对话也应能参考新状态。分析允许得出“维持原安排”。

### R07：变化后的重新规划

用户在对话中补充临时会议、任务超时或状态变化，或主动要求重排时，利用已有背景提出调整，说明影响与取舍，无须从头问。

未完成任务需要重新判断，而非永久原样顺延；保留真实截止，不把“今天没做”当作任务已消失。已接受的调整取代原安排中对应部分。

### R08：进度、收尾和再次启动

区分未开始、进行中、阶段完成、整体完成、暂停/等待及主动放弃，不把不同结果混为完成。只根据用户反馈或明确依据更新进展，允许用户纠正。停止时按需记录停点、阻力和下一步，关闭重开应用后仍能承接。

回顾提供真实进展与可行下一步，不用未完成数量评价用户。复盘由用户按需发起，不默认增加每天必须打卡的新任务。重复经历可形成待验证的偏好建议，用户能纠正，不能把少量经历写成人格标签。

### R09：导航与展示

左侧仅是导航，包括“今日安排”“所有任务”和已完成入口，不在左侧列出具体任务。

- 默认“今日安排”：主工作区详细显示今日目标、重点任务、子任务、必要背景与休息建议。
- 点击“所有任务”：主工作区显示简洁任务列表，包含名称、已标注的重要性及任务状态或下一次安排。任务类型、重要性和名称搜索可同时使用。重复记录、背景与子任务按需查看。
- 点击“今日安排”返回。两视图不堆叠，选中态与顶部路径同步，右侧对话保持。
- 全部任务不因出现在列表中就被安排到今天；已完成入口用于查看真实完成记录。

### R10：主题与模型配置

正式应用必须支持浅色和深色切换，完整布局、控件与状态表达均须适配。视觉与控件要求见 [设计规范](设计规范.md)。

先面向个人使用，用户配置自己的模型 API Key、模型及必要的服务地址。任务与会话保存在本机，云端模型调用会发送本次所需上下文；不需要自建云端后端。没有可用模型、调用失败或取消时，已保存任务与计划仍可浏览和手动维护，不能把半段回复当作正式变更。

- 可恢复的网络或模型服务故障最多自动重试三次，显示进度并允许取消。失败后可对当前这轮手动重试，不重复追加用户消息或提交任务变更。
- 对话历史按最近活动倒序，显示本地时间，底部支持翻页和选择每页 5、10 或 20 条。最多保留 1000 个会话，超限时淘汰最旧的非当前会话。确认删除会清理聊天记录、草稿和会话方案，不撤销已保存任务、安排与明确偏好。

### R11：重复任务

- 任务可设置每天、每周选定星期，或在指定起止日期内每天重复。新规则可以从今天开始。修改规则从下一天生效，日期范围含首尾。
- 每个符合规则的本地日期生成一次实例，自动进入「今日安排」的行动顺序。当天已有安排时复用其顺序、范围与完成状态。打开「本次详情」可修改执行范围，完成只记本次。「从今天移除」跳过单次且不计入历史，支持当天撤销。应用关闭期间按原规则补记错过。
- 规则以外已有的手动安排显示为「临时安排」，仍可修改范围或移出当日。今日批量管理分别处理重复实例、临时安排和普通任务的永久删除。
- 删除重复模板会停止生成新实例，保留此前产生的实例，包括今天尚待处理的这次。「所有任务 → 重复记录」按任务查看完成、错过及每次执行范围，也能找回已删除模板的记录。
- 用户可在对话中创建重复任务、为现有任务设置或修改规则、删除模板，以及调整今天这次的范围、完成或恢复未完成、从今天移除或撤销移除。对话操作遵循协商与执行边界。执行范围可能同时指当天实例和后续规则时，先核实用户要改的是哪一项。

## 4. 协商与执行边界

| 输入或事件 | 应有结果 |
| --- | --- |
| “把英语移到明天” | 明确授权的修改直接执行并反馈，无须重复确认同一决定。 |
| Agent 主动建议减量、拆分或改期 | 给出具体方案、理由与取舍，用户接受后落地。 |
| “行，按这个来” | 接受本轮清楚表达的方案，不扩展为永久授权。 |
| 只接受英语调整 | 只改接受部分，报告等未接受部分保持原样。 |
| “报告好烦” | 理解阻力并协助，不据此自动取消或改期。 |
| 手改能量 / 切换主题 / 切换导航 | 仅更新对应状态或展示，任务、方案和模型请求均不受影响。切换主题保留草稿、对话与当前视图。 |
| “重新分析一下” | 请求分析，不等于接受生成的新方案。 |

从对话提炼背景可以随交流更新；涉及目标、真实截止、完成状态或已承诺安排的实质修改，仍遵守上述规则。正式数据与建议、已接受与未接受、事实与推测必须可区分。

## 5. 任务属性

- 普通任务与子任务共用编辑器。名称必填，重要性、说明和所属任务可留空。一次性任务可设置整体状态与预计起止日期，状态默认未开始。重复任务使用 R11 的规则。
- 预计开始和预计完成可填同日、单独填写或留空，预计完成不能早于预计开始。每日安排仅记录当日范围与阶段状态，独立于任务预计日期和整体完成状态。「安排一次推进」按需展开。
- 说明用于保存仍有价值的目标、完成条件、背景、进展、阻力、下一步、硬截止及前提。简单任务可只填名称。Agent 调整预计日期时应保留说明中的硬截止和前提要求，并区分已确认事实与推测。
- 每个任务独立标注高、中、低或未设置。新任务默认未设置。任务列表默认显示各等级，按等级或未设置筛选后，批量管理作用于当前列表中的选中任务。标注供 Agent 结合截止、可用时间和状态规划，由用户在任务详情修改。
- 所属任务不得形成父子循环，子任务独立维护自身属性和状态。

## 6. 可调整的默认值

根据试用观察调整可逆细节并记录理由，涉及产品边界或授权规则的变化先与用户讨论。

| 项目 | 当前默认 |
| --- | --- |
| 能量词汇 | 精力充足 / 状态平稳 / 有些疲惫 / 需要恢复；未设置时显示“尚未说明”，不是第五个等级。 |
| Agent 对能量的判断 | 可询问或建议，默认不自行覆盖用户展示的状态；状态记录来源和更新时间，过旧时核实。 |
| 快捷预设 | 点击填入可编辑输入框，用户发送后才分析；不自动发送。 |
| 计划精度 | 默认顺序与阶段目标，有明确时间条件再细化时间段；不强制固定番茄钟。 |
| 主动性 | 在会话内主动判断和追问；不默认后台巡查、通知、定时分析或强制打卡。 |
| 长期理解 | 保存任务相关背景和明确偏好；对话推测不自动变成永久个人事实，支持查看、纠正与删除。 |
| 主题 | 浅色 / 深色 / 跟随系统，初始跟随系统。保存用户选择并在重启后恢复，只有跟随系统时才响应系统主题变化。 |
| 品牌与平台 | 暂用“息序”；以当前 Windows 桌面环境验证，其他系统打包能力不得未经验证就宣称完成。 |

## 7. 核心验收

在相应功能落地后按场景验证结果。模型措辞可变，建议覆盖同一会话中的连续变化。

具体对话、初始条件和评审方式见 [Agent 场景用例](Agent场景用例.md)。实际验证范围分别见 [测试说明](../tests/README.md) 和 [Agent 验证记录](Agent验证记录.md)。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 模糊目标，信息不全 | 针对关键条件交流并形成初步任务，不要求长表单、不编造缺失事实。 |
| A02 | 给已有任务补充截止并纠正背景 | 更新同一任务及相关理解，不重复创建；后续使用修正结果。 |
| A03 | 三小时容量、六小时任务或冲突硬截止 | 明确冲突与取舍，协商方案，不假称全部可完成，不默认加班。 |
| A04 | 大任务拆分并接受 | 真正形成可跟踪子任务、完成条件和当前入口；阶段完成不误标整体完成。 |
| A05 | 无法启动 / 连续受挫 | 结合背景给出具体推进或恢复路径，允许改变方法和继续挑战，不只说加油。 |
| A06 | 方案同时调整两项任务，只接受一项 / 拒绝另一项 | 对照原安排，只有已接受的一项发生变化。后续建议采用用户补充的新约束。 |
| A07 | 临时事件与任务超时 | 利用上下文调整，说明损失与保留，不重复询问全部背景，不无尽顺延。 |
| A08 | 手改能量后不发消息 | 展示和存储更新，模型请求数为零，现有安排不变。 |
| A09 | 连续改能量后发预设 / 稍后另行对话 | 使用最后状态和当前任务，预设可编辑，发送后才分析；分析不等于接受。 |
| A10 | 用户说“休息没恢复”或“难题让我有精神” | 修正判断，不套固定恢复公式，不机械削减困难任务。 |
| A11 | 总任务多于今日安排，推进其中一项后切换两视图 | 两个主工作区视图显示同一项的更新后进度。未安排的任务只列在所有任务中，左栏保持为导航，右侧对话保留。 |
| A12 | 关闭重开 / 下次继续任务 | 保留任务、背景、状态、真实进展、对话及待接受方案，能从停点继续。 |
| A13 | 模型失败、取消或重复接受 | 不产生半成品任务和重复变更；现有数据仍可使用，错误明确可恢复。 |
| A14 | 浅深主题及系统主题切换 | 所有视图、弹层、输入和状态可读，选择持久保存，无明显主题闪烁；任务、输入草稿、方案与模型请求不受切换影响。 |
| A15 | 重复任务的当天操作、跨日重开及模板删除 | 当天只出现一次。移除可在当天撤销且未撤销的日期不计入历史。关闭应用期间符合规则的未完成日期可查为错过。删除模板后已生成的实例保留。 |
