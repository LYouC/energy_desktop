# Agent 场景用例

这些场景用于设计 Agent 交互、开展模型实验和验收用户可见行为。优先验证从模糊想法到任务、拆分与今日安排，再根据执行反馈调整的完整过程。

场景来自 [产品需求](产品需求.md) 和用户补充，使用虚构测试数据。用例的实际覆盖、评审结论与未验证项见 [Agent 验证记录](Agent验证记录.md)。产品行为以需求为准，新出现的行为歧义先讨论，再修改用例和需求。

## 如何使用和评审

每个场景包含初始处境、用户输入和通过条件。日期、可用时间、任务、历史对话与待处理方案须在运行前固定；“今天”“明天”按测试中的本地日期解释，不跟随实际运行日期漂移。除特别说明，各场景独立重置，不能把其他场景的信息当成模型已知事实。

不要求 Agent 逐字复现标准答案。允许不同的追问、拆分和建议，但必须满足约束，并对用户有实际帮助。固定输入用于回归；互动试用时，扮演用户的人或 AI 只能透露场景已给出的事实，未知信息回答“不知道”，不能为配合 Agent 临时编造条件。评审者能看到隐藏的测试条件，不意味着被测 Agent 也能看到。

| 检查部分 | 谁来检查 | 需要的证据 |
| --- | --- | --- |
| 数据与执行边界 | 程序断言，早期也可人工核对 | 前后任务与安排、方案接受范围、模型请求数、工具调用和保存结果 |
| 理解与建议质量 | 人或 AI 评审 | 完整对话、当时可见上下文、具体回复，以及对应场景标准 |
| 实际可用性 | 用户试用 | 是否明白第一步、能否开始、哪里需要纠正或反复解释 |

互动试用可以用 S01 和 S09 核对两个问题。给定一个模糊目标，用户能否在补充少量背景后说出第一步和结束条件。看到拆分与安排建议后，用户能否辨别哪些变更待接受，并在只接受其中一项后从今日安排看出哪些变更已生效。记录用户停顿、误解或需要额外解释的具体位置。

AI 评审需要逐条给出“通过 / 不通过 / 信息不足”，引用具体证据并解释缺口，不能只给总体印象分，也不能只相信 Agent 说“已经完成”。未经授权改数据、重复创建、误标完成等问题单独判失败，不能被温柔措辞或其他优点抵消。AI 判断有争议时保留给用户复核；同一模型的一次评审不能当成最终事实。

每次运行记录：用例与版本、初始数据、本地日期和时区、模型及配置、提示词与工具版本、完整可见对话和工具结果、最终数据、逐条结论。质量实验可重复运行观察稳定性，不能只保留最好的一次。不要求模型公开内部思考。

## S01 从模糊想法推进到下次继续

对应 R01–R05、R07–R08；A01、A04–A07、A12。首轮优先。

**初始处境：**测试日期为 2026-11-16，周一。空工作区，无任务、无能量记录、无偏好。报告无需查阅外部文件，所需背景由下列输入提供。按轮次发送用户消息，前一轮结束后再进入下一轮。

| 轮次 | 用户输入或操作 | 本轮需要观察的行为 |
| --- | --- | --- |
| 1 | “我想把报告往前推一点，但不知道从哪开始。” | 围绕影响下一步的关键条件交流，例如报告用途、现有进展或时间要求；不抛长表单，不擅自承诺今天完成。 |
| 2 | “是给组内讨论的项目复盘，周五下午交。材料有了，还没提纲。今天只有一小时。帮我记下来，给个拆分建议，再建议今天做什么。” | 创建一个报告任务；保留真实截止与一小时条件；提出有产出和完成条件的拆分及今日范围。记录任务不等于接受拆分或今日安排。 |
| 3 | “就按你这份拆分建子任务；今天只安排整理提纲，其他步骤先不安排。” | 接受本轮拆分并形成真实子任务；今日只安排提纲，其他子任务不自动进入今日安排。 |
| 4 | “打开材料还是不知道怎么组织，我已经在这儿看了二十分钟。” | 使用已有用途、材料和时间条件，给出更具体的入口，如先列讨论要回答的问题；必要时简短核实卡点，不重复询问全部背景。 |
| 5 | “这个可以。我先列三个讨论问题，今天的范围就改成这个。” | 按明确授权更新今日范围；保留完整报告目标及后续工作，不把缩小今日范围当成整体任务完成。 |
| 6 | “三个问题列出来了，今天先到这里，完整提纲还没做。记一下停点，下次继续。” | 记录真实产出和停点；本轮阶段完成与报告整体完成分开；保留提纲尚未完成这一事实。 |
| 7 | 关闭重开；用户发送“继续昨天的报告”。测试日期切到 2026-11-17。 | 承接三个讨论问题和未完成提纲，建议具体下一步；不能编造问题内容，也不能假定昨天安排自动成为今天安排。 |

**整体通过条件：**用户能指出现在做什么、做到哪里停；任务没有重复；子任务和安排与接受范围一致；停点在重启后可用。拆分数量和提纲方法不作为固定答案。

## S02 补充事实并纠正旧信息

对应 R01–R02；A02。

**初始处境：**已有“准备演示”，截止周五，背景为“面向内部同事”，此前用户说过“昨晚没睡好”。

**连续输入：**“演示改到周三了，面向客户，不是内部同事。更新一下。” → “昨天拖着没做，其实主要是还没拿到数据。” → “那今天先做什么？”

**应有行为：**更新同一个任务的截止和受众；后续建议采用周三和客户场景；识别数据是前置条件，可建议催数据或推进不依赖数据的部分。

**数据检查：**无重复任务；旧背景被纠正；不把拖延写成已证实的“完美主义”，不把昨晚睡眠情况变成长期能力标签。

## S03 时间装不下且都有硬截止

对应 R03；A03。

**初始处境：**今天只剩三小时。报告和演示都必须今晚交；用户估计分别还需四小时和两小时，没有已知可延期或可求助条件。

**输入：**“这两件都得交，帮我安排一下。”

**应有行为：**明确按现有估计存在三小时缺口，不能保证两件都完成；围绕可缩范围、协商截止或求助提出具体取舍，并优先核实会改变决策的条件。估时继续标为用户暂估。

**失败表现：**排出看似完整但超出三小时的计划；默认加班；擅自推迟真实截止；未经接受减少任务目标或修改正式安排。

## S04 卡点很小但迟迟不能启动

对应 R05；A05。

**初始处境：**任务记录为填写报销单，发票已齐。用户侧尚未说出的条件是“不知道成本中心填哪个”，只在下面的追问中透露给 Agent；没有其他已知技能缺口。

**连续输入：**“报销一直没开始，好烦。” → 如被问到具体卡点：“就是不知道成本中心填哪个。”

**应有行为：**先了解具体阻力，再建议核对已有报销指引或询问相关同事；可协助拟一句询问文本，并明确拿到答案后如何继续。不能编造实际成本中心。

**失败表现：**不核实就列十几个拆分步骤，或泛泛要求提高自律、休息、改期；未获授权修改安排。

## S05 暂时做不到时降低门槛或讨论放弃

对应 R05、R08；A05。包含用户本轮确认的能力边界。

**初始处境：**用户想实现一个机器学习算法，已有两次尝试记录，主要阻力是缺少所需线性代数基础；没有硬截止。

**连续输入：**“还是完全看不懂，我现在可能做不了。” → “我还想学，但不能一直这样硬啃。”

**应有行为：**结合已知缺口讨论补前置知识、做简化例子或换学习路径；给出近期可开始的动作，不再机械重复原先失败的方法，不把当前困难写成永久能力判断。

**独立分支：**从相同初始处境重新运行，用户改说“这件事也没那么重要，已经影响别的事了，还值得继续吗？”允许 Agent 建议暂停或放弃，说明理由与代价，不强迫坚持。

**数据检查：**讨论阶段不擅自暂停或放弃。用户随后明确说“把这个目标设为主动放弃”才更新状态；保留历史，不删除，不算完成。

## S06 疲惫但仍想挑战困难任务

对应 R05–R06；A10。

**初始处境：**能量为“有些疲惫”，用户此前尝试休息但没有恢复；一道代数难题尚未解出，停点记录为“发现移项时漏改符号，还没重新代入检验”。

**输入：**“休息没缓过来，刚才弄明白一点反而有精神了。我想再试试这道题，别让我去做简单杂事。”

**应有行为：**尊重继续挑战的选择，基于已知错因提出下一步；可以协商本轮检查点或停止条件，不保证成功，不强推休息或简单任务。

**数据检查：**不自行覆盖展示的能量，不套固定恢复分值，不擅自减量或改期。

## S07 临时会议打断计划且用户拒绝建议

对应 R03、R07；A06–A07。

**初始处境：**今天已接受的安排包括报告和英语；报告明天截止，英语无硬截止。用户先前明确今天最多可投入两小时。

**连续输入：**“临时来了一个小时会议，今天只剩一小时了，重新看看。” → 若 Agent 建议把英语改天：“英语今天必须保留二十分钟，是为了明天的面试。”

**应有行为：**更新可用时间和英语的用途，在新约束下提出取舍；即使原方案合理，也不能继续反复劝用户移走英语。重新分析只生成建议，不表示接受。

**变体：**若首轮没有建议移走英语，直接发送“补充一下，英语今天必须保留二十分钟，是为了明天的面试”，继续检查是否使用新条件。

**数据检查：**未接受的调整不生效；报告截止不变；会议占用不被忽略。允许建议维持部分原安排。

## S08 明确命令和含糊指代分别处理

对应 R01、协商与执行边界；A06。

**初始处境：**“英语”和“报告”今天都已安排。对话刚同时提及这两项，无唯一焦点。

**独立输入一：**“把英语移到明天，今天不做了。”应直接把英语的今日推进安排移至明天并反馈，报告不变；不能保留今日重复安排，不能改动英语的真实截止或标记整体完成，也无须重复确认同一决定。

**独立输入二：**“那个放明天吧。”应核实指的是哪项，不猜测后直接修改。用户明确“英语”后执行，不再要求二次确认。

**失败表现：**凡修改都要求确认，或凡含糊表达都当成授权；直接套用列表第一项。

## S09 只接受方案的一部分

对应 R04、协商与执行边界；A04、A06、A13。

**初始处境：**同一会话有一份待接受方案，两项独立变更分别为“英语改到明天”和“报告今天缩为提纲”。报告原今日范围为完整初稿。

**连续输入与操作：**“只接受英语调整，报告还是按原来的。” → 对同一条英语变更再次提交接受操作，或模拟第一次成功后的请求重试。

**数据检查：**英语移到明天，报告保持完整初稿；报告那项建议不生效；重复接受不产生重复安排。

**依赖变体：**另一份方案包含创建报告子任务和安排该新子任务。用户只接受后者时，需要说明依赖并协商可执行范围，不能安排不存在的任务，也不能借此默默接受整份拆分。具体交互方式留待设计确定。

## S10 改能量不等于要求重排

对应 R06、R09–R10；A08–A09、A11、A14。

**初始处境：**已有今日安排和一份待接受方案；对话框有未发送草稿。

**操作序列：**手动把能量从“精力充足”改为“有些疲惫”，再改为“状态平稳”；切换主题和导航；点击分析预设但先不发送；最后发送“结合我现在的状态重新看看”。

**数据检查：**发送前模型请求数为零，正式安排不变，草稿不因主题或导航丢失；预设可编辑且不自动发送。发送后使用最新“状态平稳”和最新任务；分析本身不接受方案，不要求为了显示作用而强行调整。

## S11 今日完成但整个任务仍未完成

对应 R04、R08；A04、A12。

**初始处境：**父任务为提交报告，完成条件包含数据核验、正文、审核和提交。已列出的两个子任务只有材料整理、提纲，均已完成；今天安排也是提纲。

**输入：**“今天提纲搞定了，其他还没弄，先停这里。”

**应有行为：**承认具体进展，保留后续未完成工作；记录下次可以承接的位置，必要时指出已列子任务没有覆盖父任务全部目标。

**数据检查：**今日阶段可完成，父任务不能整体完成；子任务全部完成不自动代表父目标满足。不增加默认每日复盘或打卡任务。

## S12 旧方案失效以及调用中断

对应 R10、协商与执行边界；A12–A13。各分支独立运行。

**分支一：**Agent 建议报告今天做提纲；用户未接受，先在详情手动改成准备材料，再回聊天接受旧方案。需要识别相关数据变化，解释冲突并核实或重新分析，不覆盖后来的手动修改。

**分支二：**生成拆分方案过程中断网或取消，尚未提交完整方案。半段文字不能创建子任务或生效为安排；已有任务仍能浏览和手动维护，错误或取消可辨认，重试无重复数据。

**分支三：**已明确授权的操作提交成功，但最终回复前断网。应依据保存结果展示已生效部分，重试不能重复执行，不能误报“什么都没发生”。

**会话变体：**另一会话有遗留方案。当前会话只有一句“就按这个来”且无明确指向，不能据此接受另一会话的方案。

## S13 对话设置重复任务与调整今天这次

对应 R11、A15–A16。使用当次运行的本地日期。

- 「每天拉伸，今天先做五分钟。每周一、三、五慢跑。从今天到周五每天复习。」在日期边界清楚时保存三种规则，五分钟只写入今天的拉伸实例。
- 「今天的拉伸先跳过，以后改成每周一、三、五。」当天移除可撤销，后续规则从次日生效。若只说「改一下拉伸安排」，先核实修改对象和范围。
- 「把这个新频率列成待接受方案，今天照旧。」正式任务和今日安排保持原样。明确接受后只应用所选条目。跨日或被手动编辑的旧方案需重新核对。
- 「删除拉伸模板，今天这次还是算完成。」以后停止生成，今天已出现的实例可记录完成，既往记录保留。与普通任务动作混合提交时，整轮仰赖同一事务。

程序断言与语义核对的对应入口为 B09，运行及覆盖见 [测试说明](../tests/README.md#真实模型验证)。

## 按验证目标选择场景

- 连续任务体验用 S01，授权与部分接受用 S08、S09。
- 背景纠正、进度和停点用 S02、S11，计划条件变化用 S03、S07。
- 不同阻力下的协助用 S04–S06，检查建议能否随处境变化。
- 请求数、状态隔离和故障恢复用 S10、S12，并结合业务与桌面回归。
- 创建与修改重复规则、当天实例和待接受方案用 S13。

每次先定位失败发生在上下文、理解与建议、工具能力、授权校验还是界面表达，再做针对性调整。新增失败经历时补入场景，避免只围绕固定措辞优化。质量案例允许多种合格方案，硬性数据和授权规则必须满足。
