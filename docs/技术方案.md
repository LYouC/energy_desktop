# 技术方案

核心技术栈已确认。本文记录实现边界和开发路线，当前进度见第 4 节。

## 1. 已选技术栈

| 层 | 选型与职责 |
| --- | --- |
| 前端 | Vue 3 + TypeScript + Vite；Composition API 与 `<script setup>`。 |
| UI | shadcn-vue + Tailwind CSS；遵循双主题 [设计规范](设计规范.md)。 |
| 前端共享状态 | Pinia；保存展示与交互状态，不取代任务持久化。 |
| 桌面 | Electron；在受控 Node.js 进程运行本地应用服务。 |
| Agent | Vercel AI SDK Core + 所选模型的 provider；只使用一套核心 Agent 循环。 |
| 数据 | SQLite；具体驱动与迁移工具在实现时核验，Drizzle 可选。 |
| 结构校验 | 建议 Zod，配合业务规则校验任务、工具参数与变更方案。 |

先个人使用，自配 API Key。本地优先保存任务与会话，模型通过 API 调用，无须 Next.js、Vercel 托管、自有云端后端或强制 AI Gateway。模型可配置，但不能因接口宣称兼容，就假定其工具调用与结构化输出完全可用。

初始化时按官方文档核对 Node.js、框架和依赖的兼容范围，安装后用锁文件固定版本。SQLite 驱动还需在 Electron 自带的 Node.js 中实际验证。

## 2. 模块划分建议

```text
Vue 界面 / Pinia
    ↕ 有限、经过校验的 IPC 与流式事件
本地应用服务
    ├─ 任务、父子关系、背景与今日安排
    ├─ 规划方案的保存、接受与应用
    ├─ 能量、会话、偏好与主题设置
    ├─ SQLite 持久化
    └─ Agent 运行服务 → AI SDK Core → 模型 API
```

下面是开发时可采用的职责边界。按当前阶段需要逐步落地，具体模块和入口以实现后的 `AGENTS.md` 索引为准。

- **界面与交互**负责三栏、主题、草稿和操作反馈，用 Pinia 管理共享界面状态，通过明确的操作请求读写业务数据。
- **任务与今日安排**统一管理任务、父子关系、背景、进度和今日范围，供今日安排和所有任务共同读取。变更方案的校验和应用单独组织，负责接受范围、数据版本和重复提交。
- **Agent 对话**负责组装上下文、模型调用、工具循环、流式输出和取消。拆分、调整与受阻协助共用这一套循环。
- **桌面与本地数据**负责 Electron 主进程、受控 IPC、SQLite 迁移与持久化，以及凭据存放。能量和偏好各自通过对应操作读写，按实际复杂度决定是否单独成模块。

Agent 可通过有限工具读取任务、获取背景、保存背景补充、提出拆分和安排、执行已授权操作；不提供任意 SQL 或系统命令工具。

Electron 界面使用隔离的 preload/contextBridge 暴露有限能力。API Key 留在受控本地执行层，使用系统保护能力保存，不进入前端持久化状态、模型提示词、日志或仓库。若未来改为产品方统一提供服务，再单独设计服务端和计费，不能在客户端嵌入共享 Key。

## 3. Agent 如何落实产品规则

### 上下文与记忆

每次用户发起分析时，按相关性加载任务、背景、当前阶段、最新能量、明确偏好和近期对话；长会话可摘要，任务事实仍以修正后的存储记录为准。先采用任务关联与查询，不默认添加向量数据库。

SDK 的运行时上下文变量不等于模型可见内容。需要显式把任务与能量写入模型消息、系统指令或工具结果；Key 只留在执行上下文。

### 分析、授权与应用

分析形成结构化方案，记录涉及任务、预期变更、理由、取舍和接受状态。模型产生的流式片段或通过结构校验的数据，仍不能直接当成用户已经接受。

模型按产品授权规则结合多轮对话判断意图与接受范围，应用绑定真实消息来源，执行层校验 ID、会话归属、版本与业务一致性。每轮用 `prepareTurn` 明确语义决定，conversation 对应交流与空 actions，changes 对应实际操作或正式方案的具体动作，每项 mode 单独表达授权。程序预演并返回回执，模型随后独立生成自然语言终答。已有安排通过源 taskId/date 原子更新或转移，语义判断通过真实对话验证。

应用时校验相关数据版本、授权范围和方案是否仍适用；方案过期应核实或重新分析，不覆盖用户后来的修改。用事务和执行标识防止半途写入与重复应用，保留必要变更记录。取消、超时或失败不能默认为成功。

### 触发边界

分别提供状态保存和发送消息的入口，模型请求由发送入口发起，在执行时从业务层读取最新能量。导航、主题、启动恢复和数据刷新使用各自的状态或查询路径。

### 前端传输

AI SDK 的 Vue 集成可选，也可自行消费 IPC 事件。现成聊天 UI 传输默认常面向 HTTP；Electron IPC 需要适配，不能认为安装一个聊天 hook 就自动连接本地服务。流式展示与最终可应用结果分开处理。

## 4. 开发路线与进度

### 2026-11-17 任务字段修订与 Agent 适配

任务模型精简为 `title/status/startDate/expectedDate/description/parentId`，保留系统字段 `id/version/updatedAt`。普通任务和子任务使用相同 schema、工厂与编辑器。日期业务校验支持空值、有效日历日期及开始不晚于完成。每日安排不再回写任务日期。

SQLite user_version 升为 2，`electron/migrations.ts` 在事务中将旧分散文本合入说明，保留任务、安排、会话和输入草稿；不从旧推进日期推测开始日期。旧待接受方案失效，旧待创建任务草稿清除；迁移失败回滚，重开不重复执行。

后续已完成 `shared/agent.ts`、`electron/agent/`、`src/features/mock.ts` 及相关测试的新字段适配。背景与停点通过 updateTask.patch.description 合并保存完整说明，子任务支持自己的预计日期。84 项回归、类型检查、标准构建和完整桌面脚本通过。真实模型已观察到日期调整、硬截止保留、今日安排隔离和子任务日期正确落地，也观察到遗漏信息及正文输出补充工具协议的失败。运行层已增加协议损坏整轮失败处理，语义完整性仍需按场景持续评估。

界面默认真实模式，提供模型设置、文本前缀预览、取消和错误恢复。本地开发凭据通过被忽略文件注入，正式应用通过系统保护能力保存 Key。SDK 原始错误输出关闭，公开配置只返回是否存在凭据。方案引用、任务版本、否定表达和运行标识幂等均有业务校验，原文动词检查仍不能证明任意自然语言授权正确。

### Agent 语义决策与对话打磨（2026-11-17）

按用户反馈移除意图、授权和否定的关键词判断，以及要求模型逐字抄写原文的执行拦截。应用绑定实际用户消息，模型自行概括标题、判断创建与接受范围。保留结构、任务关系、版本、会话归属和事务校验。

近期聊天改用真实 user/assistant 消息。可选会话工作记忆保存摘要与待创建内容，`readConversation` 按同会话游标查询早期原话。每轮模型用 `prepareTurn` 明确交流或操作及具体动作，程序预演后让模型读取回执，再生成自然语言终答。已有安排通过 `updateArrangement` 明确指定源安排，可原子转由子任务承接，源与目标版本、源行存在性均在接受时检查。

本轮 74 项自动回归和类型检查通过。默认推理试验出现未取得可应用结果的兼容问题，实际仍沿用已验证的 SiliconFlow 非扩展思考工具配置。真实模型多轮理解、完整落地和事实提炼的已测范围与剩余问题以 [Agent 验证记录](Agent验证记录.md) 为准。
