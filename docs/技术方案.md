# 技术方案

状态：核心选型已由用户确认；当前只有静态原型，依赖版本与运行工程尚未建立。本文约定实现边界，不把库的宣传能力当作应用已实现能力。

## 1. 已选技术栈

| 层 | 选型与职责 |
| --- | --- |
| 前端 | Vue 3 + TypeScript + Vite；Composition API 与 `<script setup>`。 |
| UI | shadcn-vue + Tailwind CSS；遵循双主题 [设计规范](设计规范.md)。 |
| 前端共享状态 | Pinia；保存展示与交互状态，不取代任务持久化。 |
| 桌面 | Electron；在受控 Node.js 进程运行本地应用服务。 |
| Agent | Vercel AI SDK Core + 所选模型的 provider；只使用一套核心 Agent 循环。 |
| 数据 | SQLite；具体驱动与迁移工具在实现时核验，Drizzle 可选。 |
| 结构校验 | 建议 Zod，配合业务规则校验任务、工具参数与变更方案。 |

先个人使用，自配 API Key。本地优先保存任务与会话，模型通过 API 调用，无须 Next.js、Vercel 托管、自有云端后端或强制 AI Gateway。模型可配置，但不能因接口宣称兼容，就假定其工具调用与结构化输出完全可用。

Pi 已作为备选评估，当前不再引入或重开比较。SDK API 和正式发布版本在落地时查对应官方文档并锁定；不拼接旧教程与 latest 文档中的不同版本接口。

## 2. 模块边界

```text
Vue 界面 / Pinia
    ↕ 有限、经过校验的 IPC 与流式事件
本地应用服务
    ├─ 任务、父子关系、背景与今日安排
    ├─ 规划方案的保存、接受与应用
    ├─ 能量、会话、偏好与主题设置
    ├─ SQLite 持久化
    └─ Agent 运行服务 → AI SDK Core → 模型 API
```

模块按职责分离，具体目录可由实现者决定；新增重要模块配短说明，不先建设过度抽象的通用框架。

- **界面层**只展示数据、收集明确操作、消费事件；浏览模型文本时不能据此直接改数据库。主题状态与任务规划事件分开。
- **业务层**是总任务单、今日安排与进展的统一依据。校验父子关系、任务是否存在、完成条件和用户接受范围，避免重复任务与循环依赖。
- **存储层**持久保存任务、子任务、背景、阶段目标/计划、方案及其状态、会话、离散能量和更新时间、偏好与主题选择。不要只存一条不断变长的聊天历史。
- **Agent 层**处理上下文、模型调用、工具循环、流式输出及取消。先用一个规划 Agent 贯穿完整场景；拆分和鼓励不要求预先拆成多个 Agent。

Agent 可通过有限工具读取任务、获取背景、保存背景补充、提出拆分和安排、执行已授权操作；不提供任意 SQL 或系统命令工具。

Electron 界面使用隔离的 preload/contextBridge 暴露有限能力。API Key 留在受控本地执行层，使用系统保护能力保存，不进入前端持久化状态、模型提示词、日志或仓库。若未来改为产品方统一提供服务，再单独设计服务端和计费，不能在客户端嵌入共享 Key。

## 3. Agent 如何落实产品规则

### 上下文与记忆

每次用户发起分析时，按相关性加载任务、背景、当前阶段、最新能量、明确偏好和近期对话；长会话可摘要，任务事实仍以修正后的存储记录为准。先采用任务关联与查询，不默认添加向量数据库。

SDK 的运行时上下文变量不等于模型可见内容。需要显式把任务与能量写入模型消息、系统指令或工具结果；Key 只留在执行上下文。

### 分析、授权与应用

分析形成结构化方案，记录涉及任务、预期变更、理由、取舍和接受状态。模型产生的流式片段或通过结构校验的数据，仍不能直接当成用户已经接受。

用户明确授权的操作按范围执行；Agent 主动建议的变更由用户接受后应用，部分接受只应用对应部分。SDK 的工具审批可辅助交互，方案和接受范围仍由产品保存。

应用时校验相关数据版本、授权范围和方案是否仍适用；方案过期应核实或重新分析，不覆盖用户后来的修改。用事务和执行标识防止半途写入与重复应用，保留必要变更记录。取消、超时或失败不能默认为成功。

### 触发边界

手改能量只保存并展示；发送预设时才读取最新状态并调用模型。导航、主题、启动恢复和普通数据刷新不应被绑定为自动模型请求。切换主题不清空草稿、对话或方案。

### 前端传输

AI SDK 的 Vue 集成可选，也可自行消费 IPC 事件。现成聊天 UI 传输默认常面向 HTTP；Electron IPC 需要适配，不能认为安装一个聊天 hook 就自动连接本地服务。流式展示与最终可应用结果分开处理。

## 4. 实现与验证顺序

1. 建立 Vue/Electron 工程、受控 IPC、SQLite 迁移与语义主题变量；保留当前布局与两个主视图。
2. 打通完整流程：表达大任务 → 提炼背景 → 提出子任务/今日计划 → 用户接受 → 实际保存展示 → 重启后继续。
3. 覆盖 [产品验收](产品需求.md#7-核心验收)：受阻、部分接受、临时变化、阶段与整体完成、能量与分析解耦、错误恢复和双主题。
4. 验证所选模型/provider 的工具调用、结构化结果、流式与取消；验证 Electron 自带 Node、数据库驱动及目标平台打包兼容性。

这是工程验证顺序，不是缩减当前产品范围。任务图、外部 Todo 和云端账号不在当前实现范围。实际完成一段后更新 README 的状态；新增脚本后再写真实运行命令，不预先编造已存在的构建入口。
