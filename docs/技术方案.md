# 技术方案

交付目标见 [开发计划](开发计划.md)，用户行为与验收条件见 [产品需求](产品需求.md)。

## 技术路线与关键决策

| 决策 | 理由与取舍 |
| --- | --- |
| 本地优先的 Electron 桌面应用，用户自配模型 | 个人工作区在本机，手动任务操作可独立于模型服务使用。Agent 调用外部模型时发送本轮所需上下文，其工具兼容性和语义表现需按服务与模型验证。 |
| Vue 3、TypeScript、Vite、Pinia、shadcn-vue 和 Tailwind CSS | 用 Vue 和 Pinia 组织工作台的展示与交互状态，用共用组件和语义配色维护浅深主题。业务数据由本地服务统一读写。 |
| Vercel AI SDK Core 单工具循环，Zod 校验边界数据 | 澄清、任务拆分、安排调整和受阻协助复用同一条运行路径。模型可以判断对话语义，程序通过有限工具、结构校验和业务操作控制可执行范围。 |
| Electron 内置 `node:sqlite` 保存带版本的工作区快照 | 个人工作区的任务、安排、方案和会话可一次原子保存。查询在工作区数据上进行，写入保存整份快照。数据量或查询成本明显增长时，再评估细分表结构。 |
| 使用工作区和按需查询构建 Agent 上下文 | 工作区是任务事实的依据。近期对话和会话摘要帮助承接前文，模型可按需查询任务和当前会话原文。 |

## 系统架构与模块边界

```text
Vue / Pinia 工作台
    ↕ preload 暴露的有限 IPC 与运行事件
Electron 桌面宿主
    ├─ 领域命令 → SQLite 工作区
    ├─ Agent 运行 → AI SDK Core → 用户配置的模型服务
    │      └─ 读取工作区、预演业务动作、提交整轮结果
    └─ 模型配置与系统凭据保护
```

桌面宿主装配窗口、IPC、Agent 和数据库。领域层维护任务、安排、重复规则与方案。持久化层在事务内执行领域命令或应用 Agent 的整轮结果。Agent 通过宿主提供的接口读写工作区，模型配置通过宿主接入系统凭据保护。 [模块索引](../AGENTS.md#已落地模块索引)

## 关键运行流程

- **手动操作**通过 IPC 进入主进程。主进程校验参数，持久化层核对工作区版本并在事务中执行领域命令。界面根据返回状态刷新。手动更改能量走这条路径，Agent 在用户发送消息后读取最新状态。
- **Agent 对话**先保存用户消息，再从当前工作区和会话组装上下文。模型可查询任务、当前会话历史和容量计算结果，决定继续交流、执行明确授权的动作或提出待接受方案。程序预演动作并返回业务回执，模型据此生成可流式预览的终答。动作、方案、记忆与助手回复在最终事务中一起保存，应用以保存结果判定是否生效。
- **近期任务查询**是 Agent 工具循环中的只读操作。工具以本轮工作区日期为锚点，校验一至七天的窗口，复用今日入队资格筛选候选。对今日两区之外的已有任务提交整项今日安排建议，或提交带 `todayScope` 的拆分建议时，运行层核对任务是否来自本轮候选查询。实际移期使用不同的原日期和目标日期，并在应用时核对原安排。
- **一键优化**复用 Agent 对话。已安排事项或预计今天完成的未安排任务仍有待处理项时即可发起。消息写入时保留草稿，工具预演只允许待接受的变更。拆分建议可在同一张调整卡中建立子任务及当日安排。开发版在模型传输入口捕获请求体，并按会话、轮次与请求顺序展示。历史仅保留在主进程内存中。
- **接受方案**由对话或界面发起。对话中的确认引用当前会话的 `proposalId` 和 `cardIds`，界面用 `respondToCard` 处理单张卡。领域层按最新工作区核对卡片、任务和当天安排版本及业务关系。普通安排按卡片日期应用。界面接受成功时同一事务提交卡片和业务数据，业务校验失败时只保存卡片的失败原因。对话预演失败会回滚并返回工具错误。

对话的授权、方案接受和取消过程可在 [Agent 流程说明](agent-flow.html) 中逐步查看。工具协议和重试限制见 [Agent 模块说明](../src/agent/README.md)。

## 重复任务的日期与状态

每条重复规则挂在一个顶层任务上。用顶层任务 ID 和应做日期标识轮次，各层子任务共享这个轮次。启用区间、当天安排和历史完成各有保存位置，供总表和今日页按各自的日期条件读取。过去错过的日期无需格外生成待办或历史行。父子继承与完成约束见 [重复任务使用说明](重复任务.md)。

任务内容集中编辑，今日条目随任务和规则刷新。这个约定消除了旧版中任务与本次执行范围可以独立编辑、删除任务后今日条目仍留在页面的情况。完成历史单独保存，使改规则和停止排期都能保留已经勾选的轮次。

| 数据 | 职责 |
| --- | --- |
| `tasks[].recurrence` | 保存顶层任务配置的规则。子任务沿所属关系读取同一规则。任务内容由两个页面共用。 |
| `repeatSchedules` | 每个配置了重复规则的顶层任务一条。用 `since` 界定创建、改规则或恢复后可计算的起点。`previousDate` 可承接改规则前最近且依然符合新规则的过去轮次。`skippedDate` 用来判定最近一次跳过。`stoppedOn` 区分停止及当天完成卡片是否继续显示。 |
| `arrangements` | 重复部分只保留应做日为当前本地日期的条目，用于今日顺序、聚焦、子任务状态及方案验证。标记内只保存安排版本，名称及祖先从任务读取。执行范围复用任务名称写入共享安排字段，补勾过去的轮次直接写完成历史。 |
| `repeatCompletions` | 以顶层任务 ID 和应做日期记录勾选日期，是累计次数与历史的来源。子任务共享所在轮次，子任务的单独勾选进度记录在当天安排。 |
| `skippedOccurrences` | 仅保留当天可撤销的跳过快照和位置。规则来源的 `skippedDate` 在跨日后仍用于区分跳过和未完成。 |

顶层任务归入父任务时，原规则与尚未执行的排期失效，已有完成记录仍按原任务 ID 保存。新关系下的安排由新父任务的规则重新计算。

领域层按以下顺序处理：

1. `effectiveRecurrences` 解析规则来源。`latestRecurrenceDate` 根据规则和启用区间找截至今天的最近应做日。`recurrenceProgress` 再合并跳过、停止和完成记录，给出显示日期、逾期、可勾选资格和撤销目标。未来日期可以显示，到了应做日才能勾选。
2. `synchronizeRecurrence` 更新当天的重复安排。工作区读取和写入复用这一步。总表用轮次状态计算勾选与日期，今日页用实际当天条目展现顺序。父任务当轮完成时，各层子任务在两个视图中都显示为完成，包括当轮新加入的子任务。
3. 勾选和撤销通过 `setOccurrenceDone` 校验操作日期及轮次，再更新完成记录或当天子任务状态。上级已完成时，先撤销上级的当轮完成，才可单独撤销子任务完成。跳过、改规则、停止、恢复和删除也走领域命令。删除对任务树级联清理工作区记录，原有对话仍可查阅。
4. Agent 计划携带预演所用的本地日期和任务版本。移动重复分组时提升受影响后代的任务版本。修改今天轮次时另核对安排快照，勾选规则所属任务还要核对本次覆盖的后代范围。处理逾期轮次用应做日期指向原轮，用预演日期防止跨日误用。

业务行为见 [产品需求 R11](产品需求.md#r11重复任务)，入口见 [领域模块](../src/domain/README.md#重复任务) 和 [Agent 工具边界](../src/agent/README.md#重复任务动作)。

## 数据一致性与失败恢复

- 任务版本与当天安排版本用于发现过期方案，工作区版本用于并发写入校验。Agent 等待模型时工作区仍可变化，最终提交前会重新核对规划所依据的快照。
- 用户消息与成功的助手回复通过运行标识关联。暂时性网络或服务故障的自动重试只包住模型生成。手动重试复用运行标识并重新读取工作区，已成功提交的请求可在重启后识别。
- 最终事务前取消、超时或生成失败时，已保存的用户消息仍可在会话中查看，业务动作与助手回复需在成功运行后才会保存。方案应用失败时，事务保留上一次一致的状态。
- 预计日期和整体完成状态记录在任务上。每日安排保存执行内容，重复完成历史保存应做日期与勾选日期。开发工作区只读写当前格式。 [持久化模块说明](../src/persistence/README.md)

## 授权、凭据与模型边界

应用将动作绑定到实际用户消息，由模型结合对话判断对象、接受范围和授权。程序负责校验结构、引用关系、版本和业务一致性。Agent 主动提出的变更保存为方案，用户明确授权的具体动作可直接提交。场景中的授权判断和事实提炼质量通过 [Agent 验证记录](Agent验证记录.md) 核对。

渲染端经隔离的 preload 调用桌面能力。模型工具只暴露工作区相关的查询和有限业务动作。设置中的 API Key 由本地执行层通过 Electron `safeStorage` 加密保存，再用于模型请求认证。界面读取设置时仅获得公开配置和凭据是否可用。模型消息携带指令及本轮所需的任务与会话上下文。界面展示脱敏后的错误。
