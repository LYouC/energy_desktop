## Agent 感知调整卡的点击结果

点击接受或拒绝后，Agent 能读取最新工作区，但下一轮缺少稳定的点击与执行记录，难以承接「刚才那项继续」之类的说法。

待确认如何关联原卡，如何记录接受成功、明确拒绝与执行失败，保留多久，以及用户能否在对话历史中看到。

## 逾期任务

- 哪些情况算逾期？分别考虑预计完成日期、说明里的硬截止、未完成的旧安排和错过的重复实例。
- 在「所有任务」和「今日安排」如何展示？何时沿用原日期、提示重新安排、继续推进、改期或关闭任务？
- 未完成的旧安排是否自动带到今天？如何保留原范围、进度和硬截止？
- 用户发起今日分析时，Agent 何时纳入逾期事项？如何权衡截止、重要性与容量？

## 任务进度

跨日任务需要记录已产出、停点和剩余工作。当前可在任务说明里记录，结构化进度尚待讨论。 [收尾和再次启动](产品需求.md#r08收尾和再次启动)

- 记录哪些信息，如何更新与纠正？一次性任务、父子任务和重复实例的进度如何关联到各自的完成状态？
- 部分工作已完成后，改期如何保留原执行记录、实际启动日期和硬截止？「逾期」显示与消除见 [逾期任务](#逾期任务)。
- 今日勾选应记录本次进展还是整体完成？Agent 如何根据剩余范围安排工作，以及哪些进度或日期变更需确认？

## 任务顺序拖动

希望通过拖动调整任务顺序。现有顺序来自「今日安排」上方的行动列表，父任务与当天已安排的子任务成组。

- 明确可拖动的视图、分区和对象，包括重复实例、已完成项、子任务和聚焦组。决定「所有任务」是否需要保存自定义顺序。
- 明确拖动采用插入还是交换，父子是否整组移动，以及跨父任务、跨今日分区和跨日放置的含义。
- 确定拖动手柄、键盘等价操作和撤销需要。列表内调序只改变顺序，另需确认是否改变聚焦，以及新顺序如何影响 Agent 待接受的方案。
