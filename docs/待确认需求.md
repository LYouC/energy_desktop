# 待确认需求

这里记录试用反馈、临时想法和等待用户确认的业务规则。开发目标与验收方向见 [开发计划](开发计划.md#后续事项)。用户确认后，将相应行为和验收条件写入 [产品需求](产品需求.md)，并更新本页条目的状态和关联文档。

## 方案呈现与确认

**反馈**　Agent 建议把「整理发票」改到明天时，更新任务说明和预计完成日期、取消今天的安排、增加明天的安排分别显示为三项。每项重复显示同一段理由，并各有接受与拒绝入口。用户需要把三项连起来，才能看清一次改期的整体效果。

**已交付**　每轮一个任务只展示一张调整建议卡。卡内改期与预计日期一起接受或拒绝，独立任务可分别处理。 [协商与执行边界](产品需求.md#4-协商与执行边界) · [开发计划](开发计划.md#已交付)
