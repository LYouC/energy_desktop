# 重复任务使用说明

[产品需求 R11](产品需求.md#r11重复任务) 定义规则和验收条件，[技术方案](技术方案.md#重复任务的日期与状态) 说明数据如何记录。

## 设置规则与新增子任务

只在顶层任务设置重复。可以选每天、每周自选星期，或在指定日期范围内每天执行。日期范围包含开始和结束当天。应用按本地日期判断应做日。

子任务逐层沿用父任务的规则。挂在一次性父任务下就是一次性任务，挂在重复父任务下就随整组进入同一轮。子任务详情显示沿用的规则，修改频率请打开顶层任务。子任务可以有自己的名称、说明和完成进度。

| 场景                                       | 今日安排与任务状态                                                                                                                                                                           |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 新建重复任务，今天符合规则                 | 父任务和各层子任务今天一起出现。待做子任务可在当天执行卡片内勾选。                                                                                                                           |
| 新建重复任务，首轮尚未到期                 | 「所有任务」显示首轮日期，到了应做日才出现完成框。                                                                                                                                           |
| 父任务本轮待做时新增子任务                 | 今天是应做日且当前轮正在执行时，新子项以待做状态加入；否则随父任务的下一次安排出现。                                                                                                         |
| 父任务本轮完成后新增子任务                 | 新子项当行直接显示该轮已完成。当天是应做日时显示「今日已完成」，完成次数仍由父任务的那条记录计算。                                                                                           |
| 某个中层子任务先完成后，再往它下面加子任务 | 新增下级同样在这一轮显示已完成。整组的完成次数仍由顶层任务计算。                                                                                                                             |
| 今天已跳过整组后再新增子任务               | 新子项沿用整组的跳过结果，随下一次安排进入新一轮。                                                                                                                                           |
| 改变所属任务                               | 原父任务的轮次进度与新父任务分开计算。若原来是配置了重复的顶层任务，归入父任务后按新父任务的规则安排，此前已经记录的完成历史随任务保留。脱离父任务成为顶层任务时，可在任务详情重新设置重复。 |

例如，11 月 28 日勾选了「每日打卡」，再新增「喝 8 杯水」。它在「所有任务」里立即显示「今日已完成」，「每日打卡」仍是完成一次。11 月 29 日新一轮开始时，两项都从待做开始。

## 勾选与切换轮次

| 场景                               | 操作与结果                                                                                             |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 到了应做日                         | 可从「今日安排」或「所有任务」完成顶层任务的当轮。完成时，各层子任务随该轮显示为完成。                 |
| 只完成一个子任务                   | 可在上级待做时勾选该子任务，它自己的下级随之完成。顶层任务可继续推进，累计次数等顶层任务完成时才增加。 |
| 上级已完成，想撤销某个子任务       | 先撤销该轮已完成的上级，再单独撤销子任务。恢复上级时，子任务原有的完成进度可继续保留。                 |
| 当轮已完成，下一轮还未到           | 「所有任务」保留当前轮的完成状态，行尾同时显示下一次日期。到下一应做日切换为新一轮。                   |
| 错过应做日                         | 最近有效的未完成轮次留在「所有任务」，应做日期标红。下一轮到来前可补勾，记录原应做日和实际勾选日。     |
| 补勾或撤销过去的一轮               | 用同一行的完成框操作。该轮属于过去的日期，结果显示在「所有任务」和完成历史中。                         |
| 固定日期范围已结束，最后一轮还待做 | 最后一轮继续显示逾期。补勾后显示「重复已结束」。撤销后回到最后一轮逾期。                               |
| 看到下次日期，想提前完成           | 等到应做日再勾选。第一次未到期或跳过本轮时，列表行首显示静态标记。                                     |

## 跳过、改规则、停止与删除

| 场景                 | 操作与结果                                                                                                                 |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 跳过今天的顶层任务   | 「今日安排」移出这一轮及其子任务。「所有任务」显示下一次日期或「重复已结束」。累计完成次数维持原值。                       |
| 只跳过今天的一个子项 | 从今日队列移出这条子项。父任务按现有计划执行，子项后续仍沿用父任务规则。                                                   |
| 撤销跳过             | 在当天、规则仍适用时恢复安排。界面的撤销提示会短暂保留。                                                                   |
| 修改顶层规则         | 父子任务一同使用新规则。今天符合就刷新当天安排，排除今天就移出今日安排。当日改回且已有父任务完成记录时，整轮恢复为已完成。 |
| 停止与恢复           | 顶层任务控制整组。停止时移出当天待做的轮次，保留当天已完成的卡片和历史。恢复时从当日按现有规则判断，停用期间的日期不补排。 |
| 删除顶层任务         | 同时删除各层子任务、安排、跳过记录和完成历史。                                                                             |

## 通过对话操作

可以说「给每日打卡加个子任务，喝 8 杯水」或「把每日打卡改为周一、三、五」。第一句在原规则下加子任务，第二句调整整组频率。若只要求改变某个子任务的频率，Agent 会说明该项沿用父任务安排，修改父任务频率需要明确授权。

Agent 使用同一套轮次校验。明确授权的操作可以直接执行，建议中的变更经接受后生效。方案接受时会复核日期、任务和当天安排。验证入口见 [测试说明](../tests/README.md#重复任务验证)。
